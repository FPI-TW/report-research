# 研報觀點變化雷達設計規格

日期：2026-07-13
狀態：實作中（實作計畫見 2026-07-15 附錄與 `~/.claude/plans` 觀點雷達計畫）。
依賴：Phase 2 結構化訊號（`report_signal`）、標的頁與既有研報來源連結。

## 目標

在標的頁提供「研報觀點變化雷達」：先以**跨券商總覽**呈現市場共識、分歧與近期轉折，再讓使用者展開**單一券商歷程**，了解每次評等、目標價、EPS 與文字論點如何改變，且所有變化都可回到原始研報。

第一版只描述研報觀點如何改變，不產生買賣建議、不推送通知，也不把券商目標價包裝為系統預測。

## 使用體驗

使用者在標的頁開啟「觀點變化雷達」。預設檢視近 90 天，並可切換 30 天、180 天與全部歷程。

### 跨券商總覽

1. **共識快照**：最新評等分布、目標價中位數與區間、EPS 中位數、資料截至日。
2. **近期變化**：上調／下調評等、目標價或 EPS 修正的券商數與幅度。
3. **四個論點維度**：展望、催化劑、風險、估值各自呈現「轉強／轉弱／分歧擴大／無顯著變化」。
4. **變化事件卡**：只顯示有實質差異且附有證據的事件，例如「A 券商下調 2026 EPS，同時把需求風險從次要升為主要論點」。
5. **券商清單**：顯示各券商最新訊號與最近一個變化，點擊後才載入完整時間線。

### 單一券商歷程

依報告日期排序，逐份顯示數值快照、相對前一份可比較報告的差異、四個論點的變化、證據片段與原始研報連結。使用者可看見該券商「為何」轉變，而非只看到一個匯總箭頭。

## 資料模型

新增 `research.report_signal`，一列代表「一份研報 × 一個標的」的不可覆寫歷史快照。報告可涵蓋多個 `stock_targets`，因此每個標的各存一列。

必要欄位：

| 類別 | 欄位／語意 |
|---|---|
| 身分與時間 | `id`、`report_id`、`market`、`instrument_code`、`broker`、`report_date`、`created_at` |
| 評等 | `rating_raw`、`rating_normalized`（`buy / overweight / neutral / underweight / sell / unknown`） |
| 目標價 | `target_price`、`target_currency`、`target_horizon`、`target_price_evidence` |
| EPS | `eps_estimates` JSONB；每筆含 fiscal year／period、currency、value、unit、evidence |
| 論點 | `thesis_dimensions` JSONB；展望／催化劑／風險／估值各含 stance、摘要與 evidence |
| 可追溯性 | `extraction_version`、`extraction_status`、`raw_payload`、`error_detail` |

`report_id + market + instrument_code` 必須唯一；`market + instrument_code` 是雷達的標的鍵，避免不同市場的相同代碼誤合併。`extraction_status` 至少區分 `pending`、`valid`、`partial`、`rejected`；格式不完整或無法正規化時保留原始資料與錯誤，但不阻塞研報檢索。

建立索引：`(market, instrument_code, report_date DESC)`、`(market, instrument_code, broker, report_date DESC)` 與 `report_id` 索引，以支援總覽與券商時間線。

## 擷取與正規化

新增可 checkpoint-resume 的批次工作，對已入庫的研究報告依 `stock_targets` 擷取訊號。LLM 只負責依固定 JSON schema 擷取數值與論點；Python 負責驗證、正規化、寫入與重跑。

- 評等保留原文，並映射到共同五級尺度；無法可靠映射則為 `unknown`，不納入分布計數。
- 目標價必須保存幣別；不同幣別不換算、不混入跨券商中位數。
- EPS 只在相同會計年度／期間、幣別與單位一致時比較；不一致時顯示為不可比較。
- 四個論點維度必須附來源片段；未取得足夠證據則維度為空，不由模型補寫。
- 每次擷取都保存 schema／prompt 版本，未來調整可比較或重跑。

## 比較與聚合規則

所有差異由 Python 決定性計算，讀取雷達時不呼叫 LLM。

### 單一券商

同一券商、同一標的的最新有效訊號與前一份「可比較」有效訊號比較：

- 評等：以共同五級尺度判定上調、下調或持平；`unknown` 不產生方向性事件。
- 目標價：需幣別相同；計算絕對與百分比變化。
- EPS：只比較相同 fiscal year／period、幣別與單位。
- 論點：比較各維度 stance；相同 stance 但證據不足時不產生事件。

### 跨券商

彙總各券商的**最新有效訊號**，不把同一券商的舊報告計入當前共識：

- 評等顯示分布與自窗期起點以來的淨新增／減少券商數。
- 目標價以同幣別群組分別顯示中位數、上下四分位與資料筆數。
- EPS 以 fiscal year／period 與幣別群組分別顯示中位數及修正方向。
- 論點維度彙總同券商前後的變化，不把券商之間原有風格差異誤判為轉折；若正反立場比例接近或資料不足，標示「分歧擴大」或「資料不足」。

所有摘要都附資料截至日、樣本數與可比較限制。超出所選窗期的舊訊號不放入近期變化，但在「全部歷程」仍可檢視。

## 後端介面

### 跨券商總覽

`GET /api/instrument/{code}/radar?market=TW&window=30|90|180|all`

回傳：

- 標的、窗期、`as_of`、資料覆蓋狀態。
- 評等、目標價與 EPS 的共識快照與變化統計。
- 四個論點維度的摘要。
- 近期變化事件卡（含 broker、report date、diff、evidence、report link）。
- 券商清單與其最近變化摘要。

### 單一券商歷程

`GET /api/instrument/{code}/radar/brokers/{broker}?market=TW&window=30|90|180|all`

回傳依日期排序的快照與前後差異。詳細歷程延遲載入，避免跨券商頁初始載入過重。

兩個端點皆維持既有登入保護；`market` 為必要參數、標的不存在回 404、窗期或市場非法回 422、沒有有效訊號回 200 加空狀態資料，不把「尚未擷取」誤報為無研報。

## 前端與狀態

在既有標的頁增加雷達區塊，順序固定為：共識快照 → 四維論點 → 近期事件 → 券商清單。選取券商後展開時間線與來源連結。

畫面須提供：

- 載入骨架、無訊號、部分訊號與不可比較資料的明確狀態。
- 指標定義與比較限制的說明，避免使用者把目標價或 EPS 中位數當成系統預測。
- 每張事件卡直接連回原始研報，而非只顯示模型摘要。

## 失敗處理與可觀測性

- 擷取錯誤只影響該 `report_id + market + instrument_code`，不影響其他報告、搜尋或問答。
- 批次工作可從 `pending`／`partial`／`rejected` 重跑，並記錄完成數、失敗數、schema 版本與耗時。
- API 對缺少數值、幣別不一致、EPS 期間不同、無前一份券商報告等情況回傳可讀原因，不假造趨勢。
- 記錄雷達查詢耗時、回傳樣本數與空狀態原因，供後續調整索引與擷取覆蓋率。

## 驗收與測試

### 服務層

- 評等上調／下調／持平／unknown 的正規化與比較。
- 目標價同幣別才比較；不同幣別不混算。
- EPS 只比較相同年度、期間、幣別、單位。
- 同券商只以最新有效快照代表跨券商共識。
- 舊報告不被列入近期變化；無前一份報告不產生假事件。
- 論點的轉強、轉弱、分歧、資料不足與來源連結正確。

### API 與前端

- 30／90／180／全部歷程窗期、404、422、無訊號與部分訊號。
- 總覽 API 不載入券商完整時間線；展開後才請求券商端點。
- 事件卡與時間線可開啟正確原始研報。
- 空狀態、資料不足與不可比較狀態可理解且不暗示投資建議。

### 人工抽樣

以跨券商、單一券商連續報告、多幣別與缺欄研報建立固定樣本，逐筆核對評等、目標價、EPS 與四維論點的來源片段。擷取品質未達可接受門檻時，先改善 schema／prompt／正規化規則，不直接回填全語料。

## 非目標

- 推播、訂閱、Email／訊息通知。
- 個人化買賣建議、投資組合配置與交易執行。
- 把不同幣別的目標價或 EPS 強制換算成單一數字。
- 讀取雷達時即時呼叫 LLM 或使用未持久化的模型摘要。
